## 1. Decisions I need from you

These are the things I could not settle on your behalf. Nothing is blocked on them — the work is
done either way — but each is a judgement you own.

### 1.1 Folding was replaced by an outline. Overrule me if you disagree.

You approved "collapse a service block to one line, plus a minimap". I did not build it, and this is
the one place I departed from what you agreed.

Folding means hiding lines, and a text box cannot hide lines. The only way is to cut the folded text
out of the very buffer that gets saved. Every fold would leave the thing on screen and the thing
written to disk as two different documents, held together by bookkeeping — against the rule that a
hand-authored file is never destroyed. For a file that is usually under 150 lines, that is a bad
trade.

**What you have instead:** an **Outline** button in the editor header. It lists the file's top-level
blocks, and each service indented underneath, in file order with line numbers. Click one to jump
there. It only ever reads the file.

If you want real folding anyway, say so and I will build it — but I would want to talk through how we
guarantee a fold can never reach a save.

### 1.2 Images are not marked, only paths. Accept or push back.

You approved "underline host paths that don't exist **and image references**". Paths are done. I
deliberately did not mark images.

An image not being on the server is the **normal** state of every stack you have not started yet.
Telling that apart from a typo needs a call out to the registry — slow, and offline half the time.
Any marker would therefore be wrong on every new stack, which is exactly how people learn to ignore
the gutter. The data is available if we find a use for it as neutral information (for example, in the
hover panel: "this image isn't on the server yet, it will be downloaded").

### 1.3 The recursive delete, from `PLAN_13.md`

Still open from earlier, and still not needed until file handling starts. Today, deleting a stack
refuses outright if the folder holds anything but the compose file and a `.env`. Once you can upload
files, that guard blocks nearly every delete, so it becomes a list-and-confirm.

**The decision:** confirming will delete sub-folders and their contents. It is guarded — every entry
is resolved and checked to be inside the stack folder, and symlinks are skipped — but nothing in the
plugin deletes a directory tree today, and I do not want to add that on my own say-so.

### 1.4 Are the syntax colours right now?

You said washed out; I raised them from a 60/40 mix towards the text colour to 45/55. That 45 is a
floor, not a preference — below it the palest colour in the set (the Unraid orange) stops clearing
the readability threshold on a light background. If you want them stronger than this, we would have
to give up guaranteed legibility on one theme or the other, or hand-pick a separate palette per
theme. Your call; it is one number per line to change.

### 1.5 The 134 key descriptions — worth a skim

Hovering any compose key now shows a one-line plain-English explanation. There are 134 of them and
**they are meant to become the form's field help too**, so the wording matters more than the
plumbing. Two examples:

> **Volumes** — Mounts a folder or file from the server into the container, written as
> host:container — /mnt/user/media:/data shares that folder with the container.

> **Published ports** — Makes a port inside the container reachable from your network, written as
> outside:inside — 8080:80 puts the container's port 80 on port 8080 of the server.

They are in `compose-model.js`, in the `DESCRIPTIONS` table. Skim a dozen and tell me if the register
is right.

| — | The health check bug from `PLAN_14.md` |

**How it works, in one paragraph, in case it matters later.** The pane is a stack of transparent
layers over an ordinary text box: line numbers, highlight bands, and a coloured copy of the text. The
text box's own text is made invisible, so what you see is the copy and what you type into is still a
real text box — which is why the caret, selection, undo, copy-paste and non-English keyboards all
still behave natively. It works because the box never wraps and every line is exactly the same
height, so line 40 is always at forty line-heights down. That one fact is what everything else hangs
off.

## 4. Bugs found and fixed on the way

Worth listing because several were the quiet kind.

1. **The health check bug you reported.** My written hypothesis was wrong, which is why I had the
   work reproduce it as a failing test before changing anything. The real cause: the command box and
   the mode dropdown are two boxes writing one line, so each reads the other's value from the file —
   and a guard meant for "the user cleared the box" fired on a mode switch, making the switch do
   nothing. After that the file said `NONE`, so every keystroke in the command box was discarded.
   Silently, permanently. `PLAN_14.md` has the full account.
2. **Writes that fail now say so.** The reason the above went unnoticed is that a form box with
   nowhere to write returned quietly. It now tells you. That is the change most likely to catch the
   *next* bug of this kind.
3. **Search highlights failed the contrast threshold** — 3.2:1 for a string, where 4.5 is the bar.
   The coloured text sits above the highlight, so the highlight becomes its background. Fixed by
   weakening the fill and letting an outline carry the "you are here".
4. **A path-checking hole in the new server endpoint.** Found by the hostile-input test, not by
   reading. Details in section 5.
5. **`^` did not mean "start of line"** in regex search, so searching `^services` found nothing.
6. Smaller ones: line elements built without their class (empty lines would have collapsed and
   thrown every line below out of step); a repaint that stopped at the first unchanged line and so
   painted nothing at all after an undo; indent guides measuring from behind the line numbers; guides
   drawn three-quarters of a pixel wide, which no browser can draw; stale highlights surviving a
   close; a name collision that would have silently replaced one of the parser's own functions.

## 5. The one security-relevant piece

A4b added the first new server endpoint. It takes a list of paths **out of a file you are typing** and
says whether each exists — so it is the most attackable thing added.

It does `realpath` and `is_dir` only. No shell, no directory listing, no recursion. It caps a batch at
200. For anything outside the folders it is allowed to look in it answers **"skipped", never
"missing"** — because "missing" is itself an answer, and returning it for `/etc/shadow` would turn
this into a way to map the server's filesystem.

**The hostile-input test caught a real hole.** Containment was checked only by resolving the path,
which resolves nothing at all unless every part of it already exists — so `../../../../etc` aimed
through a stack folder that had not been created kept its `..` intact, and the check then found a
containing folder inside the root and allowed it. It leaked nothing (it never looked at the target),
but the verdict was wrong. Containment is now checked **twice by two different means**: resolving
cannot handle a path whose middle does not exist, and a text-level `..` collapse cannot see a
symlink. Each covers the other's blind spot and both must agree.

The test lives at `local/test_check_paths.php` (gitignored). Run it on the server any time:

```sh
plink -ssh -batch -pw <pw> root@192.168.200.88 "php /tmp/test_check_paths.php"
```

## 6. Known limits, so they are not surprises

- **The remembered health check command lives in memory, not in the file.** Switch to *No check*,
  then type in the Compose pane (which re-reads the file from scratch), then switch back — it will
  not return. By then it is genuinely gone from the file, so there is nothing to give back.
- **Only the visible part of the file gets marks drawn.** Search highlights, gutter dots and path
  underlines are drawn for what is on screen, deliberately — the counts still cover the whole file.
  If you go looking for a mark on a line you cannot see, it will not be there until you scroll to it.
- **Pressing Enter repaints more than typing does.** Typing inside a line repaints that one line;
  Enter shifts every line below it. There is a cheaper way to do it if a large file ever feels slow,
  noted in `PLAN_12.md` — I did not build it because it should be measured first, and that needs your
  eyes on a real file.
- **The path check needs `/mnt`.** Paths outside it are not checked at all, silently. That covers
  things like `/var/run/docker.sock`, which are legitimate and are left alone rather than flagged.
