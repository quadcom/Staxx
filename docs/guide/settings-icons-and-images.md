# Icons and images tab

<!-- index: 83 | the Icons and images tab: container icons, reading an image's documentation and StaXX fields. -->

The **Icons and images** tab, in [Settings](settings.md), controls how StaXX finds an icon for each
container and how much it reads about an image when you add one.

![The Icons and images tab in full: Container icons with a centred row of six sample icons above its attribution line and dropdown, Image documentation with its dropdown, Watch the publisher's own examples with its dropdown, and the StaXX fields box with its Add missing StaXX fields to every stack link](../images/guide/settings-icons-tab.png)

| Setting | Choices | Default | What it does |
|---|---|---|---|
| Container icons | Find one for each container / Leave a container with no icon showing its initials | Find one for each container | Finds an icon for each service that has none, matched by its name. Off, a service without an icon shows a coloured tile with its initials. |
| Image documentation | Read it automatically / Do not look anything up | Read it automatically | Reads the page an image's publisher wrote about it when you add or open a stack, and uses that to start you with a fuller file, fill in the stack's description, category, author and links, and offer a health check if the publisher provides one. Only the image's name is sent. Off, you start from a bare four-line file and nothing leaves the server. |
| Watch the publisher's own examples | Look, during the same check / Do not look | Look | Looks, during the update check, at the example set-up file the image's publisher keeps on GitHub, so StaXX can later point out a setting the publisher has added that your stack does not have. Only the project's address leaves your server. Off, no examples are looked at. |
| StaXX fields | — | — | **Add missing StaXX fields to every stack** checks each stack for its icon, links and description, and offers to add blank lines for any that are missing, ready for you to fill in. It shows what would be added before writing anything, and never changes what a file already says. |
